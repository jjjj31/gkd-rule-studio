# Spec：用户订阅规则库与应用搜索

日期：2026-10-13。状态：本地代码已实现；184 个项目测试和 19 项浏览器流程检查通过，真实 GKD 设备验收待补。

GitHub 规格与进度入口：[#3](https://github.com/jjjj31/gkd-rule-studio/issues/3)。

## 目标与典型流程

用户把多个订阅链接添加到生成器，把这些订阅当作规则库：搜索软件名，按规则组的原名称选择所需功能，再逐组测试、复制或导入 GKD。主要价值是按需选择现成功能；现有规则失效后寻找替代规则也可沿用这个流程。

示例：添加两个订阅 → 搜索“淘宝” → 查看该应用在两个来源中的规则组 → 选择“关闭更新弹窗” → 直接复制完整 App 规则片段，或连接 GKD 后测试／导入。整个过程不需要创建快照或 AI session。

本次会话的最新决策替代本地旧稿 `docs/rule-search-design.md` 中相冲突的方案。作者维护的清单、镜像仓库与 CI 均不是本功能的前置条件。GitHub spec Issue 是需求与任务进度的权威入口；本文件保留发布正文。

## 已确认的产品决策

| 决策 | 第一版行为 |
| --- | --- |
| 来源 | 用户将订阅链接添加到生成器，可添加多个来源 |
| 搜索入口 | 首页独立入口，浏览、搜索、复制无需连接 GKD 或选择快照 |
| 搜索对象 | 按应用名查找用户已添加的订阅中的应用 |
| 选择单位 | 完整规则组，保留原名称、说明、公共参数和组内规则 |
| 操作方式 | 逐组操作，每组提供独立的“测试 / 复制 / 导入”操作 |
| 测试 | 同一功能逐组测试，用户手动判断是否有效 |
| 测试门槛 | 测试可选；未测试也能复制、导入，并显示“未测试” |
| 已有规则 | 自动暂停 GKD 中已有规则不属于必经流程 |
| 刷新 | 添加来源时下载，之后用户手动刷新；成功数据保存在本地供离线搜索 |
| 更新关系 | 导入 GKD 的内容是固定副本，保留来源和版本记录，不自动跟随原订阅 |
| GKD 目标 | 按项目当前接入方式：支持本地规则接口的 Beta 可直接导入；正式版提供规则片段复制与手动添加说明 |

## 行为规格

### S1．订阅来源与缓存

- 接受 HTTP(S) 订阅文件链接，读取 JSON/JSON5。粘贴 GitHub 仓库网页或 HTML 时给出“请提供订阅文件链接”的提示。
- 每个来源记录输入链接、订阅 id、名称、作者（如有）、version、上次成功刷新时间，以及最近一次错误（如有）。刷新时间是本机下载成功时间，不冒充作者发布时间。
- 相同规范化输入链接再次添加时复用该来源，不新增重复记录。不同链接作为独立来源，不仅凭订阅 id 合并。
- 首次下载并解析成功后才加入可搜索来源。刷新成功后整体替换该来源快照；下载、解析或持久化失败时保留上次成功内容和版本，提示失败并允许重试。
- 重启后恢复已添加来源和完整可用规则；断网时继续搜索和复制缓存内容。应用启动或打开搜索页不会自动联网刷新。
- 支持删除生成器中的来源；删除来源不会修改已写入 GKD 的固定副本或已保存的来源记录。
- 网络请求通过项目现有网络通道；验证 URL 与输入结构，使用 JSON5 解析器读取数据。解析错误定位到来源或规则组，合法规则组仍可浏览。

### S2．搜索与结果

- 搜索应用名，忽略首尾空白和英文大小写，支持子串匹配；包名也可作为定位应用的辅助输入。应用身份以包名区分，同名不同包名分别显示。
- 相同包名在多个来源中出现时归到同一应用，保留各来源提供的应用名用于匹配。
- 应用详情按来源展示规则组。不同来源的同名组、同 key 组分别保留，不按名称或选择器自动合并。
- 应用详情提供规则名称搜索，忽略首尾空白与英文大小写，支持子串匹配；显示匹配数量与总组数，无匹配时提示更换关键词。进入其他应用时清空规则搜索。
- 每个组显示原名称、desc（如有）、来源名称、订阅版本、规则条数和本次测试状态；默认禁用的组显示源规则的禁用状态。
- 提供无来源、无结果、加载中、刷新失败且有缓存、规则组结构不支持等状态。
- 界面使用简短标签和状态，省略常驻的操作教程、功能复述和入口副标题；错误保留必要原因，源规则自身的名称与描述完整保留。

### S3．复制与规则完整性

- 复制无需设备连接和测试结果。通过现有跨平台剪贴板入口复制，成功与失败都有反馈。
- 默认复制 App 规则片段：包含应用包名、应用名和所选完整规则组，可粘贴到 GKD“本地订阅 → 应用规则”的添加位置。复制的是规则正文，不以订阅链接代替。
- 来源链接、订阅名称与版本可放入合法 JSON5 注释，或在生成器中单独保存；来源元数据不改变规则执行字段。
- 复制结果不携带源订阅的自动更新地址，也不夹带该应用其他独立功能或整个订阅。
- 保留规则与规则组的所有原始执行字段、组内步骤顺序、key 引用及快照链接。必要的表示形式转换必须保持语义等价；源数据保持不可变。
- 支持 GKD 文档允许的规则简写与对象／数组表示；不把只含 `anyMatches` 等合法条件的规则误判为缺少 `matches`。依据：[RawAppGroup](https://gkd.li/api/interfaces/rawappgroup)、[RawAppRule](https://gkd.li/api/interfaces/rawapprule)。
- 重编号只在目标命名空间确有冲突时进行，并同时重映射引用。`scopeKeys` 允许规则引用其他规则组内的 key，`actionCdKey` 与 `actionMaximumKey` 也有执行语义。依据：[RawGroupProps](https://gkd.li/api/interfaces/rawgroupprops)、[RawCommonProps](https://gkd.li/api/interfaces/rawcommonprops)。
- 第一版的交付单位是单个独立规则组。若组有无法在本组解析的跨组引用，明确显示所需依赖与限制，保留浏览及查看原文，阻止输出或发送不完整的可执行片段；自动打包其他规则组留待后续范围。此项是保证“完整规则组”语义的兼容性边界。

### S4．设备测试

- 测试所需应用信息直接来自订阅，连接 GKD 后即可开始，不要求快照、选点或 AI session。
- 连接地址与 GKD 目标版本统一在首页设置；规则库直接复用首页连接，页面内不重复提供连接表单。
- 规则库每次启动一组测试；切换时结束上一组规则库测试，避免同一功能同时运行多份实现。
- 使用现有 `updateSubscription` 临时测试通道；与生成候选的现有测试集合共用一个同步入口，维护完整的当前内存订阅，避免相互覆盖或把外部组按同名合并。
- 对源文件中默认禁用的组，用户点击“测试”表示在临时测试期间启用该组；原始缓存和复制内容仍保留源配置。
- 用户在目标应用复现场景并手动标记有效／无效，能结束测试。发送成功只表示规则已送达，不自动视为功能有效。
- 同步失败、连接丢失时提示失败，不显示已生效；结束或切换测试时同步移除旧组，同时保留其他仍在测试的生成候选。
- 不自动关闭 GKD 已有订阅，不把“关闭已有规则”设成操作前置条件。

### S5．固定副本导入

- 一键导入要求连接支持 `localRules/append` 的目标，不要求测试过或标记有效。原有生成候选的测试门槛保持其现有行为。
- 单次只追加所选完整规则组及应用信息。默认禁用等源设置保持原样，并提示用户在 GKD 中按需启用。
- 正式版目标显示手动导入说明，始终保留完整规则片段的复制入口；接口缺失时如实提示可改用复制。
- 按接口实际返回值反馈新增与跳过数量，不把全部跳过或请求失败描述成已新增。
- 保存成功后记录来源链接、订阅 id／名称／版本、应用包名、原 group key、实际导入内容和导入时间；本地规则缓存、元数据和设备写入结果区分保存。
- 再次导入同一份内容时给出清楚的重复反馈；不同来源的同名组不会在客户端被错误拼接。
- 源规则库刷新不修改已导入副本或其来源版本。重新挑选新版通过追加接口交付，不声称覆盖旧组；旧副本由用户在 GKD 中管理。
- 本地接口是否保留完整参数、是否修改 key、是否按选择器过度去重，需要在集成 ticket 中用支持的 GKD fork 实测。发现接口会改变语义时必须暴露失败／限制，不能靠客户端成功提示掩盖。

## 第一版范围边界

范围为用户自带链接、应用规则搜索和单组操作。内置订阅推荐、作者清单／镜像服务、自动刷新、批量勾选、组内单条规则选择、全局规则检索、自动暂停已有规则、自动更新已导入副本、跨组依赖自动打包不在第一版。

本地副本元数据在生成器中留存，不扩展为 GKD 本地规则的删除、覆盖或双向同步功能。

## 整体验收

当前实现及验证记录见 `docs/verification/subscription-rule-library.md`。浏览器检查使用自造订阅和模拟 GKD 接口，不能替代真实设备的规则触发和回读验证。相关 Issue 在设备验收及代码合入前保持开启。

- [ ] 添加两个自造订阅；同一应用同名组都可见，来源清楚，各自原始内容独立。
- [ ] 无设备、无快照时，从首页进入搜索；重启并断网后仍可搜索和复制。
- [ ] 一个来源刷新失败保留旧数据，另一个来源成功更新；成功版本与刷新时间准确。
- [ ] 复制结果经 JSON5 回读包含正确包名和完整组；多步 `preKeys`、共享参数、默认开关和未知扩展字段保持正确。
- [ ] 跨组引用无法独立交付时，界面明确说明限制，不输出伪装成可直接使用的缺依赖片段。
- [ ] 连设备逐组测试；切换／结束后旧测试组退出，已有生成候选测试不被清空；用户自行判断有效。
- [ ] 未测试组可一键导入支持的 Beta；正式版用户可复制完整片段并手动添加。
- [ ] 一键导入后回读或在 GKD 编辑器核对，完整参数及多步引用保持正确；重复操作、接口缺失与请求失败均反馈真实结果。
- [ ] 刷新或删除生成器来源后，GKD 中的固定副本保持导入时内容和版本记录。
