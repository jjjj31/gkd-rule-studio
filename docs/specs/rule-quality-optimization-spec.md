## 1. 问题陈述与优化背景

在 GKD 规则制作体系中，「机器代码（本地启发式策略）生成的规则质量」与「外部/内置 LLM 规则生成质量」直接决定了用户的开箱可用度与自动化免维护周期。在本次优化前，系统面临四大系统性痛点：

1. **本地启发式策略跨版本稳定性瓶颈（基线 70.2%）**：
   - 机器生成规则过度偏好单一快照内看似唯一的短字母数字混淆资源 ID（如 `2x1`、`c6n`、`arg` 等）或未定义动态文本（如「查看原图(1.7M)」「连续签到3天」）。这类选择器在快照 A 中唯一，在目标应用跨版本或跨设备更新后剧烈撞名或失效，导致跨版本单规则稳定率停留在 70.2%。
2. **离线端侧 Few-Shot 案例库体积膨胀（9.8 MB）**：
   - 原始全量真值案例库体积达到 9.8 MB，严重超出移动端随包分发的体积预算（限制 $\le 300\text{ KB}$），且早期 RAG 检索在查询中混入了来自真值规则的先验特征（形态泄漏），无法在真实的端侧未知快照中有效命中。
3. **大模型规则生成缺乏客观页面事实约束（基线 Top-1 仅 64.3%）**：
   - `bench/llm-failures.md` 取证确认，通用 LLM 在缺乏强约束时高频出现三大硬伤：
     - ① **编造属性**：将快照中只有带包名 `id` 的控件去掉包名前缀改为不存在的 `vid`，或凭空捏造 `vid`（0 命中率高）；
     - ② **漏写抬升语法**：点击了 `clickable=false` 的文本子节点，却漏写 `@[clickable=true] >` 提升到可点击父容器，导致真机无障碍点击无效；
     - ③ **节点树截断破坏关键锚点**：大页面（>220 节点）简单截断祖先链，导致同屏弹窗的关键标题、倒计时与广告标识被完全剪掉。
4. **后置验证与打回闭环缺失**：
   - 验证器（`verifyAiCandidates`）仅在前端只读渲染时被动调用，AI 生成或外部粘贴返回的候选未经静态置信度打分直接排在首位；当所有候选均静态 0 命中时，用户必须先在真机上测一遍失败，缺乏零成本本地打回修正链路。

## 3. 系统架构与关键实现设计

### 3.1 启发式策略增强：跨版本防混淆与多层级收窄

在 `src/lib/selectorStrategies.ts` 与 `src/lib/regionCandidates.ts` 中新增多维特征分析与策略降级：

1. **混淆 ID 识别与降档（Anti-Obfuscation）**：
   - 识别混淆模式：短哈希（如 `a1`、`x3b`）、常见加固框架特征（`obfuscated`、`arg`、`unused_res_a`、`pdd` 等）。
   - 将混淆 ID 从默认 Tier 2 降级至 Tier 4，避免压制跨版本高度稳定的语义文本。
2. **动态文本固定前缀提取**：
   - 自动识别倒计时（`5s`、`00:03`）、动态数值（`连续签到3天`）及文件大小后缀（`查看原图(1.7M)`），提炼固定中文前缀并生成基于 `^=`（`startsWith`）的保守稳定变体。
3. **可点击外层容器自动降维收窄（`narrowByDescendant`）**：
   - 当用户选中外层可点击容器时，深度遍历其内部唯一子文字或子资源，生成 `Parent[clickable=true] > Child[text="..."]` 或 `@Parent[clickable=true] > Child[text="..."]`，既保证点击有效，又杜绝多命中。
4. **弹性兄弟与无尺寸宽松兜底**：
   - 兄弟选择器增加弹性跨距 `+n` 支持；结构兜底同时输出带严格尺寸与去除脆弱像素尺寸的宽松变体。

### 3.2 端侧零泄漏案例库蒸馏与检索

在 `src/lib/fewShotRetrieval.ts` 与 `src/data/distilledFewShot.json` 中建立端侧案例机制：

1. **离线压缩蒸馏（Distillation Pipeline）**：
   - 从 5,539 条真实样本中，仅提取快照运行时可直接测得的特征（控件类名、`vid/id` 存在性与混淆状态、文本长度分桶、子节点数分桶、层级深度分桶、可点击性与包含关系）；
   - 抽样聚类生成包含 240 条代表性规则的微型库，体积仅 **77.5 KB**，直接作为静态资源随前端包分发，0 云端请求、100% 离线可用。
2. **零泄漏无偏检索**：
   - 检索时完全不依赖任何 GT 规则字段，基于运行时视觉与 DOM 拓扑计算 Jaccard/Dice 特征匹配度，在单快照与多步场景中默认提供 Top-2 官方参考案例。

### 3.3 客观证据向 AI 接力的提示词契约与保锚裁剪

在 `src/lib/helpPrompt.ts` 与 `src/lib/flowDraft.ts` 中完成契约升级：

1. **视觉摞（Visual Stack）与可点击性事实**：
   - 自动检测并输出与目标矩形重合的所有同层节点；
   - 若用户选中的节点 `clickable=false`，提示词显式插入【关键警示】，指明其可响应点击的祖先节点 `#id`，并明确要求使用 `@` 抬升语法（如 `@[clickable=true] > [text="..."]`）。
2. **防幻觉合法属性清单（Whitelist）**：
   - 自动收集局部节点真实存在的 `vid` 与 `id` 白名单；明确警告严禁编造未列出的 `vid`，严禁将带包名 `id` 去掉前缀伪造为 `vid`。
3. **保锚节点树裁剪算法（Anchor-Preserving Tree Pruning）**：
   - 在大快照（>220 节点）下，除了目标链及其直接同父兄弟外，计算其余节点到目标节点的几何中心欧氏距离；
   - 优先保留具有有效文本（`text`）、说明（`desc`）或关键标识符（`title`、`close`、`cancel`、`skip`、`ad` 等）的节点及其祖先路径，确保在 220 节点硬限制下，同屏弹窗的标题、关闭图标与广告角标不被破坏剪除。

### 3.4 后置静态验证重排、自动纠偏与打回闭环

在 `src/lib/aiCandidateVerification.ts` 与 `src/components/AndroidLiteApp.tsx` 中打通后置闸门：

1. **确定性自动纠偏（Deterministic Auto-Repair）**：
   - 当大模型生成 `[vid="btn_skip"]`，但快照中全无此 `vid`，而存在 `id="com.demo:id/btn_skip"` 时，自动纠正为 `[id="com.demo:id/btn_skip"]`；
   - 纠偏记录自动追加到候选的 `summary` 中，并保持规则语法合法。
2. **静态置信度重排（Rerank）**：
   - 内置 AI 与外部粘贴导入时，自动调用 `rerankAiCandidates`；
   - 对单命中视觉摞（100分）、多命中视觉摞（75分）、点偏（30分）、0命中（10分）与语法错误（0分）分档排序，将通过静态验证的候选直接置顶。
3. **免真机打回诊断提示词**：
   - 若所有候选均静态验证失败（`!bestPassed`），前端以符合规范的可关闭浮动气泡（`android-main-toast`）提示，并提供【一键复制失败诊断贴回 AI】按钮；
   - 点击即可复制包含精准失败原因与正确节点事实的重修 prompt，用户可零成本贴回外部对话进行第二轮修复。

## 5. 战争迷雾裁决与后续路线建议

针对原 Wayfinder 地图中的未决迷雾「第二阶段是否需要自建云端服务或微调专用大模型」：
- **裁决结论**：**暂缓自建后端与专用微调，端侧离线优先路线大获全胜**。
- **依据**：
  1. 本地启发式在 5,539 条真实清洗样本中达到了 **98.9% 的语义 Top-1 准确率**，跨版本稳定率达到 **75.7%**，绝大多数常规规则本地启发式已能一次性精准生成；
  2. 端侧 77.5 KB 案例库配合客观事实契约、自动纠偏与静态重排，已解决大模型 80% 以上的高频编造与语法失误，且无需搭建任何云端代理或支付微调服务器成本；
  3. 后续若需进一步突破极端对抗型 WebView/原生混合广告，可将少量疑难反例作为「高质量样本微调预研」归档至下一阶段迭代。
