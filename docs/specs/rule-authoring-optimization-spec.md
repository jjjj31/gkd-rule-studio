## 问题陈述

用户在快照的截图上选点后，可以得到候选、观察匹配范围、在设备上测试并交付规则，但仍难以回答三个关键问题：到底会点击哪个节点、规则为什么有效或无效、自动生成不理想时应该改哪里。

需求形成时，本地复现过一项正确性偏差：一条规则要求“标题存在且取消按钮存在”时，验证把标题与按钮都计为点击目标；移除标题后仍显示按钮命中。它使命中数、风险评分、首选排序和高亮失去一致的依据。2026-10-26 已实施共享规则验证修复并补回归，真实设备引擎对照仍待验收。

此外，快照上的静态命中不能证明设备运行时的事件查询范围、前置步骤、时间窗口和次数限制已经满足。用户看到多个重叠节点时难以选择，面对选择器文字难以修改，只能反复试候选或求助 AI。重复制作已有规则、只适合一张快照、捕获入口切换繁琐等问题也需要按依赖逐步解决。

## 解决方案

围绕现有“快照 → 选点 → 候选 → 验证 → 设备测试 → 复制／导入”的路径优化，不另建规则制作系统。

1. 先修正规则层验证，让点击目标、上下文、命中数和高亮遵循目标 GKD 的规则语义，并清楚区分已验证、不满足和信息不足。
2. 提供重叠节点选择、有限且可编辑的条件、简短规则摘要和有证据的失败反馈，让用户在工作区内修正规则。
3. 增加同一规则在多张快照上的正反例验证；先调查本地规则读取能力，再实现已有规则提示。
4. 对捕获后直接进入工作区、录制一次点击辅助选点，交付原生能力调查和设备原型结论；具备必要接口与设备证据后，再确定正式实现。

保留已有离线策略、场景、AI 辅助、流程和步骤、设备测试、正式版复制以及 Debug/Beta 版导入能力。AI 生成与用户编辑采用相同的验证和测试标准。

## 实现决策

1. **领域与优先级**：沿用快照、截图、节点、选点、候选、策略、首选、验证、规则、规则组、App 规则、场景、流程、步骤、设备、目标和订阅的既有含义。优先级按 A1 正确性、A2 与 B1–B4 工作区体验、C1/C2 扩展、D1/D2 可行性依次推进。
2. **一个共享验证边界**：内置策略、AI 候选、条件编辑和多快照验证复用规则层验证结果。继续使用官方选择器能力处理单个表达式，规则层组合判断不演变为另一套选择器语言。
3. **规则组合语义**：按实际支持的目标版本核对必需匹配、可选分支、排除条件、显式点击目标及规则组继承。必需匹配全部成立后，点击目标取最后一项规定的目标；上下文不能混入点击目标数。不同目标版本有差异时明确记录支持边界。
4. **部分验证**：界面已接受的字段应完整处理或显式标记未完整验证，原文保持完整。语法错误或必需条件不满足不展示为规则可执行。部分验证不等同于设备有效。
5. **事实与未知**：快照可确定的应用、Activity、条件与目标形成静态结果；事件查询起点、冷却、累计次数和前置步骤等缺少运行信息时保持未知。全树验证不宣称证明事件节点范围的运行匹配。
6. **数据一致性**：计数、评分、首选排序和画布由同一验证结果驱动；切换快照或修改候选后更新结果，旧候选的有效记录不继承给新内容。测试身份沿用现有隔离机制并覆盖内容变化。
7. **节点消歧**：复用同区域候选和祖先关系，用标签、可点击性和范围帮助切换节点；分别呈现选点节点与实际点击节点。单一明确目标不增加必经确认，支持列表选择和缩放后的范围对齐。
8. **条件子集**：首版编辑支持文字和描述等于／包含、资源 ID、类型、可点击及可见条件，条件间默认全部满足；上下文至多一个父子或相邻关系。复杂布尔表达式、正则与更多关系留在高级编辑。
9. **完整反解**：只有整条规则及其执行字段都能由条件界面表达时才允许反解；不能表达时保留高级原文入口，禁止部分映射后静默删除条件。复用统一转义和官方校验，避免维护另一套语法。
10. **编辑行为**：增删改后即时验证，取消恢复原候选；动态倒计时避免默认锁死精确值。多个匹配时解释其选择范围，不声称会点击全部节点。零匹配显示明确状态，不以生成成功代替验证通过。
11. **摘要**：从装配后的有效规则字段生成目标、动作、范围与时机摘要，考虑规则组继承。与发送测试、复制和导入的规则一致，细节放在详情。
12. **默认场景**：保留现有场景差异及策略排序。修改资源 ID 与文字优先级、Activity 范围或快速查询默认值，需另有样例与设备证据；不直接套用外部首版默认值。
13. **失败反馈**：分离客观验证结果、设备回执、用户反馈与排查建议。只有有证据才归因，缺少日志则列为待核对；复用当前测试管理与 AI 反馈入口，不另建测试系统。
14. **AI 边界**：AI 可生成和解释候选，不能把修订文本自动标为有效。内置与外部 AI 回复进入相同验证路径，反馈包含必要规则和症状信息，快照附件沿用用户显式选择。
15. **C1 接口调查与降级**：先核对 fork 的只读能力。最低需要稳定规则身份、内容、应用归属、启用状态及适用范围；缺数据时标明无法判断。此规格不虚构新端点，接口扩展先形成契约再实现。
16. **已有规则提示**：首版限适用的本地规则，异步检查不阻塞选点。分别呈现表达式重复与目标覆盖；默认查看或继续创建。只有稳定身份及明确更新契约齐备才提供替换，不按名称或选择器擅自覆盖其他规则组。读取失败保留复制／导入路径。
17. **C2 正反例**：同一条规则可关联多张快照及预期，逐张显示结果；反例误匹配必须单独提示。该功能不表示多个步骤，不改变流程装配语义；样例本地使用，回归材料采用脱敏或人工构造数据。
18. **交付兼容性**：保持规则组为导出的最小交付单位，保留执行字段及引用。正式版复制、扩展目标导入、生成候选的既有测试资格和订阅规则库未测试可用策略分别沿用其当前契约。
19. **D1 探索交付**：调查现有捕获接口与 Android 跳转能力，在设备原型中验证捕获、打开工作区与返回，并记录权限、其他窗口、失败与临时快照生命周期。能力不足时交付阻碍及所需契约，不宣称产品入口已完成。
20. **D2 探索交付**：一次点击或长按只用于解析点击前快照的目标，成功后复用候选链路。必须能够暂停并恢复 GKD 原有执行状态，可靠区分录制事件；没有事件、画面变化或目标不可靠时失败并回到选点。Compose 等框架可观察性须由本项目设备证据说明。
21. **持久化**：不改变 GKD 规则语言或订阅结构。复用现有快照、候选和测试身份；如多快照预期等确需新本地数据，只保存必要关联并兼容旧数据，不通过附加数据替代规则原文本身。

## 测试决策

1. **主要接缝（用户已确认）**：以现有 Android 工作区的用户操作为入口，贯穿选点、生成／编辑、验证展示、测试与交付；只在设备 HTTP、剪贴板和 AI 等外部边界提供受控响应。内部使用真实的选择器引擎、规则装配和状态逻辑，不为每个内部模块增加注入入口。
2. **好测试的定义**：给定快照、规则和用户操作，断言可观察的目标、计数、摘要、状态、失败提示及对外交付内容；不绑定内部函数调用次数、组件层级或评分实现细节。
3. **A1 回归**：通过共享规则验证入口覆盖标题与按钮都存在、标题缺失、目标缺失、多目标、显式点击目标、非法表达式及已支持组合条件；前序复现必须转为可重复回归。补测最终候选的计数、排序所用结果与画布一致。
4. **现有先例**：沿用项目已有的人工快照样例与官方选择器匹配回归、规则装配和转义回归、测试状态隔离及 HTTP 请求契约检查。单个细节只有在高层测试难以定位重要语义时补充独立回归，不创建通用测试框架。
5. **工作区行为**：复用项目既有浏览器流程检查方式，覆盖重叠节点切换、列表选择、条件编辑与取消、快照切换、动态倒计时、复杂规则高级回退，以及规则变化后旧测试结果失效。
6. **一致性**：同一份有效规则的摘要、验证、复制内容、设备测试内容及导入内容语义一致；候选间和快照间状态不串用。不得用快照“验证通过”自动推出设备“测试有效”。
7. **失败与降级**：在外部边界模拟发送失败、无接口、超时和部分数据，验证未知状态、草稿保留、重试与复制路径；没有证据时不得显示已启用或已覆盖。
8. **C1 契约**：接口明确后测试本地规则启用范围、相同选择器与相同目标的区别、不同规则组身份、读取失败和缺字段降级；接口不可用时验证能力说明，不能以模拟接口通过宣称设备已支持。
9. **C2 样例**：覆盖重复标签／ID、倒计时变化、广告消失后的快照、相似节点与广告热区；正反例逐张断言，不能用平均结果替代失败报告。
10. **设备验收边界**：Android WebView 上验收缩放、选点、列表与返回行为；在具体正式版和扩展目标上核对代表性规则匹配与交付，记录版本及观察结果。模拟浏览器响应不代替设备行为证据。
11. **D1/D2 验证**：只在开展探索时运行原生能力实验，覆盖权限丢失、捕获中变化、原生 View／WebView／Compose、长按、自行消失目标，以及引擎暂停恢复。结果限定到实际版本、设备和提供方，不从外部模拟器报告推定本项目支持。
12. **执行检查**：实现时运行相关既有测试及类型检查；UI 与设备语义变化补对应验收记录。本次规格编写未实现功能，也未把历史测试结果作为本规格已通过的证据。

## 范围外

- 新的选择器语言、第二套规则引擎、GKD 订阅结构重设计，以及将工作区整体重写为另一套系统。
- 一次性在条件界面支持全部布尔表达式、正则、任意结构关系、坐标定位与复杂多步骤规则；这些仍通过既有高级能力处理。
