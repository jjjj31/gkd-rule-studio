# T1：订阅来源、完整 JSON5 解析与本地缓存

关联规格：[#3](https://github.com/jjjj31/gkd-rule-studio/issues/3)。对应 S1、S3 的输入与完整性约束。

GitHub ticket：[#4](https://github.com/jjjj31/gkd-rule-studio/issues/4)。实施状态以 GitHub Issue 为准。

## 交付结果

用户添加多个订阅文件链接后，生成器能下载、解析并保存完整内容；重启和离线时仍可使用。其他 ticket 可按“来源 + 应用包名 + 原 group key”取得未被合并或重编号的完整规则组。

## 工作范围

- 建立来源与成功快照的数据结构；保存源版本、作者、输入链接和成功刷新时间。
- 通过现有网络通道加载 HTTP(S) 文件；处理超时、非成功状态、HTML、非法 JSON5、结构错误和缓存存储失败。
- 支持添加、手动刷新、删除来源；相同输入链接复用来源，刷新成功再替换，失败保留旧快照。
- 实现完整规则组解析及交付前检查；支持规则简写和 GKD 合法匹配字段，保留未被项目现有类型枚举的字段。
- 生成带应用信息的单组交付对象；保持源快照不可变，识别本组无法解析的外部 key 引用并返回可展示的限制原因。
- 本阶段提供可复用的加载／缓存与组提取能力，界面接入放在 T2。

## 代码入口与已有缺口

- `src/lib/networkExtension.ts`：现有网络通道与超时。
- `src/lib/testSubscription.ts`：当前解析器只接受数组形式的 `rules`，规则归一化要求 `matches`；添加时按组名或 key 合并并重编号，不能直接当作外部订阅的保真解析器。
- `src/types/ruleDraft.ts`：已有类型覆盖的是生成草稿，外部原始数据需要保留完整字段。
- `package.json`：已安装 JSON5；沿用项目依赖和存储方式，不为本地子串搜索引入索引服务。

## 验收条件

- [ ] 两个来源拥有相同应用、组名与 group key 时，缓存和提取结果相互独立。
- [ ] 字符串、单规则对象、字符串数组、规则对象数组都能按 GKD 格式处理；合法 `anyMatches` 规则不会因缺少 `matches` 被拒绝。
- [ ] 多步规则、共享计数／冷却引用、默认禁用状态、快照链接及扩展字段被保留；提取不会修改原对象。
- [ ] 外部引用缺失和结构损坏有明确结果，其他合法组可浏览。
- [ ] 重启／离线恢复成功内容；刷新失败不覆盖旧内容；删除来源不影响其他来源或已导入副本记录。
- [ ] 使用自造订阅夹具覆盖上述数据边界、失败保留和持久化失败；受影响的已有测试及类型检查通过。

完成时在 ticket 留下输入夹具、验证命令和结果。规则库打开时自动刷新、作者镜像和跨组依赖自动打包属于 spec 的范围边界。
