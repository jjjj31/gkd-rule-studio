# T11：一次点击辅助选点的能力调查与设备原型

优先级：P3。类型：调查／原型。状态：受外部能力阻塞，源码能力调查完成，设备原型待设备。依赖：[T10](10-capture-entry-prototype.md) 的原生路径结论，以及事件观察和 GKD 暂停／恢复能力。

对应清单 D2、用户故事 43–44（探索交付）；依据：[正式规格](../../specs/rule-authoring-optimization-spec.md)。

## 交付结果

确定能否将用户一次点击或长按可靠映射到点击前快照的节点，并复用现有选点和候选链路。交付支持边界、原型证据及继续实现／暂缓结论。

## 工作范围

- 先调查目标 GKD 是否具备事件观察及原有执行状态的暂停／恢复接口；缺能力则形成接口需求与阻碍，停止假定可录制。
- 在可控设备样例中观察原生 View、WebView、Compose、长按及自行消失目标，区分用户动作与 GKD 自己的动作。
- 一次会话只定位一次点击／长按；目标必须来自点击前快照。无事件、身份不可靠、歧义未消除或点击前画面变化时如实失败。
- 成功只替代选点步骤，继续现有候选生成与验证；失败保留截图选点。不引入“录制成功即规则有效”的状态。

## 代码入口

Android 宿主、目标 GKD 无障碍事件及执行控制能力、`src/lib/nodePicker.ts`、`src/components/AndroidLiteApp.tsx`。端点与原生实现由调查确定，不预设当前已有。

## 验收条件

- [x] 事件和暂停／恢复能力有版本与证据，明确支持与缺失范围；只停止 Rule Studio 发测试请求不算暂停 GKD。
- [ ] 可行原型在整个录制阶段保持引擎暂停，并在完成、取消、失败时恢复先前执行状态。
- [ ] 可靠事件映射到点击前快照节点，成功进入现有候选链路；无事件、页面变化或目标不可靠不猜测成功。
- [ ] 原生 View、WebView、Compose、长按、自行消失目标分别记录实测结果，未测情况明确保留。
- [ ] 跨应用事件不冒充当前目标，失败可回截图选点；记录旧 Android 与厂商差异的证据缺口。
- [x] 给出正式实现所需契约和建议范围；外部模拟器结论不替代本项目设备验收。

## 验证方式

仅在能力具备后做设备实验，记录系统、GKD、应用框架和 WebView 提供方版本。观察事件、节点身份及暂停恢复的外部行为；无设备时只能完成调查，不勾选原型验收。

## 范围外

正式发布录制入口、多动作宏／脚本回放、坐标猜测、宣称所有应用或 Android 版本可录制。
