# T09：一条规则的多快照正反例验证

优先级：P2。类型：实现。状态：实现与浏览器回归完成，待设备验收。依赖：[T01](01-rule-validation.md)、[T02](02-validation-context.md)。

对应清单 C2、用户故事 38–41；依据：[正式规格](../../specs/rule-authoring-optimization-spec.md)。

## 交付结果

用户能为同一条规则指定应该匹配与不应该匹配的快照，逐张检查目标和结果，发现只适合单张快照或会误触的候选。

## 工作范围

- 关联规则内容、快照身份与预期，不把这些样例装配成多个流程步骤；规则修改后重新验证全部样例。
- 复用共享验证入口，逐张呈现命中数、实际目标、预期是否满足及未完整验证原因。
- 建立最小脱敏／人工构造样例集，覆盖动态文案、重复标签／ID、广告消失、相似节点及广告热区。
- 如需本地持久化，只存必要关联与预期，兼容旧数据；不自动上传快照或把辅助数据写入 GKD 规则结构。

## 代码入口

`src/lib/selectorMatcher.ts`、`snapshotNormalize.ts`、`src/types/gkdSnapshot.ts`、`src/components/AndroidLiteApp.tsx`，以及现有快照与候选存储入口。与 `flowDraft.ts`、`flowSteps.ts` 的步骤语义区分。

## 验收条件

- [x] 独立组件可以添加／移除正反例，逐张显示状态、点击目标、节点 ID 和边界。
- [x] AppRule 状态复用 core 的 AI 聚合契约；正例含 `partial`／`invalid` 不冒充完整通过，反例任一已知规则误匹配时 fail 并展示实际目标。
- [x] 规则内容变化自动重算；异步结果同时校验运行 token 与规则内容身份，旧结果不能回写其他 App。
- [x] 未知条件保持 `partial / 未知`；静态通过不标为设备有效。
- [x] 样例元数据只含快照 ID、App、预期、来源标签和节点计数；当前会话内存保存，不新增持久化。
- [x] 组件不调用上传接口；样例不进入流程步骤或 GKD 规则结构。
- [x] 组件已挂入工作区并完成真实浏览器交互；加载模拟设备的另一张快照，编辑时保留并重验样例。
- [ ] 真实 Android 设备快照加载与 WebView 交互验收。

## 验证方式

通过公开验证入口检查真实样例结果，通过工作区完成添加／修改／移除与规则变化后的重算。只在涉及持久化时补对应兼容回归，不另建样例管理平台。

## 范围外

多步骤编排、云端样例库、自动收集用户快照、以静态通过证明设备动作正确。
