# T07：调查本地规则读取与更新能力

优先级：P2。类型：调查。状态：调查已完成，T08 受外部读取/更新能力阻塞。依赖：无，可与工作区优化并行。

对应清单 C1 前置、用户故事 35–37；依据：[正式规格](../../specs/rule-authoring-optimization-spec.md)。后续：[T08](08-existing-rule-detection.md)。

## 交付结果

形成可供 T08 使用的实际接口能力与契约说明，明确哪些条件可检测、哪些未知、是否支持稳定身份及更新。调查可得出“不支持”，但不能将其当成覆盖识别已实现。

## 工作范围

- 查看当前客户端、所支持 fork 的服务端实现及可用设备行为；记录版本与证据来源，分别说明源码核实和设备实测。
- 读取能力最低需要规则内容、稳定身份、应用归属、启用状态、范围与版本条件；缺字段时记录降级影响。
- 若存在明确更新接口，核对身份、冲突、字段保留和失败行为；若只有 append，说明不能据此提供覆盖／替换。
- 在本地调查记录中给出 T08 可实施范围、缺失契约及失败／不支持时的表现，不虚构端点或未经验证的字段。

## 代码入口

`src/lib/deviceApi.ts`、`gkdTarget.ts`、`subscriptionLibrary.ts`，以及 README 指向的 GKD fork。调查外部版本时按其原文核实，不能把模拟接口当成设备能力。

## 验收条件

- [ ] 记录具体目标与版本、读／写能力、源码来源和实际请求／回读证据；无法取得设备时明确缺口。
- [ ] 明确稳定身份、内容、启用状态及适用范围是否足够支持 T08，每个缺项有影响说明。
- [ ] 把表达式写入去重与已有目标覆盖检测区分开；没有更新契约时不承诺替换。
- [ ] 对接口缺失、读取失败和字段不完整给出明确降级契约，保留现有复制／导入路径。
- [ ] 调查结论形成仓库内链接，T08 根据结论标为可开始或受外部能力阻塞。

调查结论：第一项已完成源码与可用环境核对，设备请求／回读证据因无设备明确留空；后四项各有源码与降级契约证据。完整 T08 的“读取已启用且适用规则”需要新增外部接口，而非客户端单独补齐。

## 验证方式

以源码和接口可观察行为验证契约；必要时在可控设备样例上核对只读结果，不擅自覆盖用户现有规则。契约明确后再由 T08 补客户端行为回归。

## 范围外

修改上游服务端、创造新端点、实现覆盖提示、自动替换或删除规则。
