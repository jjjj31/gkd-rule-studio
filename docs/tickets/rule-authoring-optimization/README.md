## 共同验收边界

- 已确认的主测试边界：从现有 Android 工作区用户操作进入，贯穿候选、验证、测试和交付；只模拟设备 HTTP、剪贴板、AI 等外部边界，内部保留真实选择器引擎、规则装配与状态逻辑。
- 重要规则语义补现有公开验证入口的回归；复用项目已有浏览器流程检查和设备验收方式，不建立新测试框架。
- 正式版复制、Debug/Beta 版导入、生成候选测试资格与订阅规则库未测试可用策略分别保持既有契约。任何模拟发送成功都不能等同于设备测试有效。
- 实施时先按项目规则更新图谱，再核对调用方和相关测试。下列代码入口仅供导航，以实施时源码为准；不因拆 ticket 修改产品代码。
- 完成记录注明改动、运行的检查、实际结果、设备与目标版本及未验证范围。没有设备时可以记录代码与自动检查完成，但不能勾选设备验收通过。

## 状态与追踪

各 ticket 的状态和验收勾选是实施事实来源；本索引汇总依赖与当前状态，优化清单按清单项汇总。完成后同步三者，规格保留需求与边界。

状态使用：可开始、待依赖、进行中、待设备验收、已完成、受外部能力阻塞。调查得到“不支持”可以构成调查 ticket 完成，不能据此把对应实现标成已完成。
