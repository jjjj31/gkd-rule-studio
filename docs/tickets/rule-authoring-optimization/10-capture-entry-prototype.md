# T10：捕获后直接进入工作区的能力调查与设备原型

优先级：P3。类型：调查／原型。状态：源码能力调查已完成，设备原型待设备验收。依赖：无。

对应清单 D1、用户故事 42（探索交付）；依据：[正式规格](../../specs/rule-authoring-optimization-spec.md)。

## 交付结果

给出“看到目标 → 捕获快照 → 打开工作区 → 返回”的最小可行路径、设备证据与正式实现所需条件。能否形成产品入口以调查为准。

## 工作范围

- 调查现有 GKD 捕获入口与 HTTP 能力、Android 跳转／返回能力，优先复用已有入口。
- 可行时做最小设备原型，核对隐藏覆盖层、捕获、打开工作区和返回的时序；不能只用浏览器模拟证明原生能力。
- 验证权限丢失、其他窗口、采集中应用变化、空截图／无节点、进程退出，以及临时快照的保留与清理。
- 记录可用接口、缺少契约与支持范围，给出继续实现或暂缓结论；不修改用户已有持久快照来伪装临时采集。

## 代码入口

`src/lib/deviceApi.ts`、`src/components/AndroidLiteApp.tsx`、Android 宿主与清单，以及目标 GKD 的捕获服务。具体原生入口以调查结果为准。

## 验收条件

- [x] 给出实际源码／接口能力和版本，说明只用现有能力可以完成哪些环节。
- [ ] 可行路径有设备原型证据，记录捕获、打开工作区、返回与失败恢复；不可行时明确缺失接口，不虚报流程完成。
- [x] 快照与截图来源对应，窗口和权限限制明确；采集中变化无法判断时写明。
- [x] 临时与用户保存快照的生命周期清楚，进程退出或失败后不误删用户快照。
- [x] 原有快照入口仍为恢复路径，报告写明正式实现范围与尚需验证的设备情况。

## 验证方式

记录真实设备、Android 与 GKD 目标版本，提供可复现步骤、观察及必要证据。没有设备时只能提交能力调查，原型验收保持待设备状态。

## 范围外

正式发布悬浮入口、长期屏幕历史、普遍兼容所有窗口／系统版本、额外申请无关权限。
