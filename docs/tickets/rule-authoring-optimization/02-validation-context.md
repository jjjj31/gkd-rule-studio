# T02：区分快照验证、运行条件与设备测试状态

优先级：P1。类型：实现。状态：实现与浏览器回归完成，待设备验收。依赖：[T01](01-rule-validation.md)。

对应清单 A2、用户故事 8–12；依据：[正式规格](../../specs/rule-authoring-optimization-spec.md)。

## 交付结果

用户能区分当前快照上匹配了什么、哪些条件确定不满足、哪些运行条件尚不明确，以及规则是否仅已发送或已由用户确认有效。

## 工作范围

- 在 T01 的共享验证结果上承载快照身份、可确定的条件结果与未知原因；复用现有测试状态，不创建第二套状态管理。
- 根据已有信息判断应用、Activity 及静态规则条件；事件起点、冷却、累计次数和前置步骤缺少信息时保持未知。
- 全树匹配不表述为事件查询范围已经满足；显示必要的快照时间信息。
- 切换快照、目标或候选后更新对应结果，异步旧结果不得覆盖新上下文。

## 代码入口

`src/lib/selectorMatcher.ts`、`inlineRuleTesting.ts`、`candidateIdentity.ts`、`src/components/AndroidLiteApp.tsx`、`ScreenshotCanvas.tsx`，以及快照类型。

## 验收条件

- [x] 命中数明确归属当前快照；旧快照结果不会冒充当前设备状态。
- [x] 已发送测试、静态验证通过、用户确认有效是不同事实；发送成功不自动变成有效。
- [x] 可确定的应用／Activity／条件不满足有具体原因；没有运行数据的条件显示未知。
- [x] 快照全树命中不声明事件节点范围也命中；无采集前后证据时不声称能检测采集期间画面变化。
- [ ] 快照或目标切换、失败重试、异步返回乱序不串用结果，已有测试记录保持对应身份。

## 验证方式

复用验证入口、测试状态隔离回归和工作区行为检查，模拟外部设备回执与返回顺序，断言用户可见状态。Android WebView 核对切换与提示，不以模拟回执替代设备测试有效。

## 范围外

虚构运行日志、自动推断冷却／次数、改变场景默认值或采集协议。
