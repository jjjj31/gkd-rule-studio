## P0：发布前先测——快照命中框与工作区

准备至少两张同应用但目标位置不同的快照，另备有重叠父子节点、多个相同按钮、无目标及不同长宽比的快照。使用真实 Android APK、GKD HTTP 和目标应用；静态快照匹配与设备上实际执行分别记录。

- [ ] 首页连接正确渠道的 GKD，选择快照进入工作区，截图、应用名、节点和快照对应；断开后重连不混用旧数据。
- [ ] 拖动放大镜选中已知按钮：选中框贴合该节点；列表中的节点及坐标与画面对应。选择重叠的子节点、父节点后，选中框和候选随之更新。
- [ ] 选择普通候选：规则验证的命中数、实际点击目标、截图上的命中框一致；核对真实目标边界，不仅看框的数量。若有辅助节点，辅助框与点击框区分明确。
- [ ] 有兜底规则的候选：分别核对主规则与兜底规则命中的节点；混合包含无法完整验证的规则时，记录提示和框的表现，确认是否符合预期。
- [ ] 分别验证唯一命中、多目标、零命中和排除条件不满足：只有规则实际满足条件的目标才显示为点击目标；无命中时旧命中框消失，不误报成功。
- [ ] 切换普通候选、AI 候选及不同节点：显示当前选中规则的命中框，不叠加上一候选的旧框；选中框与命中框重叠时仍能辨认。
- [ ] 修改定位使目标变化或不命中，再取消/应用：预览及时更新；取消恢复原规则及框，应用后与新规则一致；不支持或不完整的条件显示待确认，不当作确定成功。
- [ ] 同应用不同快照之间来回切换，再返回上一张：截图、规则、命中框和快照身份一致，无旧框残留或迟到结果覆盖；不同应用快照也检查一次。
- [ ] 竖屏、横屏或不同截图比例、滚动和旋转/尺寸变化后，命中框仍紧贴目标；放大镜中的框与主图一致，边缘目标可选，松手、取消触摸及切后台后仍能继续操作。
- [ ] 图片尺寸与快照记录比例不一致、带黑边或裁剪时，检查是否错位并记录；尺寸异常和越界节点不得造成崩溃或误导性的显示。
- [ ] 工作区不再出现“多快照验证”和“反馈与修复”两个面板；“规则验证”和截图命中框仍可用。首页的“反馈”、AI 其他反馈路径以及多步快照切换仍可正常使用。
- [ ] 对至少一条规则在目标应用实际触发：观察是否触发、是否点对位置、页面是否达到预期；静态命中和发送成功均不能代替这一步。记录误触及无法触发的反例。

## P1：规则制作与测试闭环

- [ ] 正式版和测试版 GKD 分别测试连接、错渠道提示、PNG/WebP 快照、规则校验与保存：正式版检查复制路径，测试版检查追加导入；两种渠道均在目标应用确认实际效果。
- [ ] 普通候选详情、完整规则复制、规则摘要与快照身份正确；复杂规则/高级字段不会因查看或编辑而丢失。
- [ ] 条件编辑：文字、描述、ID、属性及父子/相邻条件分别检查；非法或不支持的表达式显示明确状态，取消保留原规则，应用后按新规则重新验证。
- [ ] 加入当前测试、发送 GKD、目标应用观察结果、标记有效/无效/结束、删除及再次同步；失败和重试有提示，不能把旧版本的测试结果算给修改后的规则。
- [ ] 断网、GKD 重启、目标渠道切换或发送失败后，显示错误并可恢复；重试后核对 GKD 中实际运行的测试集合，避免旧测试仍在运行却误以为已停止。
- [ ] 多步模式添加快照/步骤、切换、排序、编辑和测试整个流程；切回单步再返回检查步骤与当前快照不串用。
- [ ] 内置 AI 和外部 AI：生成/粘贴规则、选择候选、校验、复制与发送；无效 JSON、模型失败、取消及重试均有合理反馈，不泄漏密钥。
- [ ] 订阅规则库：刷新、搜索、查看、选择、发送测试、记录结果与重新同步；未连接或来源刷新失败时不把缓存当实时结果。

## P1：新增功能与升级兼容

- [ ] 首页和测试结果的“反馈”：必填校验、预览、功能建议分类、规则文件上传或粘贴、诊断 ZIP 手动上传、GKD 版本信息、选择性附加规则/截图/节点、截图遮挡及文字隐藏；用合成敏感信息检查预览与实际上传均已脱敏。断网草稿、重试、编号与重复提交也要检查；线上测试使用约定的测试数据并记录编号。
- [ ] 以保留数据方式从 v0.2.0 升级待测 APK：检查设置、快照命名、规则库、测试记录及 AI 配置；冷启动、前后台切换和重启后检查数据一致。安装前确认签名和包名兼容，禁止为通过测试直接卸载旧版。

## P2：异常、兼容与发布核对

- [ ] 空快照、损坏/缺截图、节点边界异常、较大快照及不同分辨率：有可理解提示，不崩溃、不长时间卡住；返回首页仍可操作。
- [ ] 网络慢、无网络、重复快速点击、权限被拒、后台系统回收：界面可恢复；记录任何残留测试订阅或未完成操作。
- [ ] 检查窄屏、系统字体放大、深浅色及横向溢出；可见文字、按钮与返回路径不被遮挡。
- [ ] 确认发布 APK 的构建来源、版本号、签名和安装升级方式；使用最终产物重新跑 P0 冒烟，不以开发构建替代。
- [ ] 发布前提高版本号并核对更新链路：当前 `package.json` 仍为 0.2.0，与线上版本相同；检查更新、下载、校验和安装均需用最终版本实测。
