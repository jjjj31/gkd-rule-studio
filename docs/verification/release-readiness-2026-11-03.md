## 仍待修复和核对

本次只拆分分支，没有顺手修复原审查缺陷。以下任务继续属于本次发行：

- **F01 / 优先：反馈脱敏范围不一致。** 只隐藏某个节点时，相同敏感文字的其他节点内容会被清理，但截图同值区域不一定同步遮挡。让最终截图与节点隐藏范围一致，并用两处出现的合成敏感值验收。相关文件：`UserFeedbackPanel.tsx`、`userFeedback.ts`。
- **F02：反馈编号兼容分支。** 两种 crypto API 都缺失时，客户端备用编号不是后端接受的 UUID；修复并用契约用例验证。
- **W01：快速切换快照的竞态。** 较早请求迟到可能覆盖最后选择，流程路径还会改绑步骤。需要最后一次选择获胜，并核对截图、节点、步骤与规则身份。
- **W02：选点框遮挡命中框。** 同一节点两种边框重合时，后绘制的选点框会覆盖命中框；需能同时辨认状态。
- **W03 / 待实机观察：** 裁剪、黑边、横竖屏等比例异常时的框对齐；等比例图片缩放本身不构成 bug。
- **R01：最终提高版本，并校验 tag、包版本、versionCode、清单及下载文件一致。** 现在仍是 0.2.0/200，不能据此向旧用户提供新版本更新。
- **R02：发布工作流补 Java 单测；更新检查不能只确认 URL 可访问。** 最终 APK 的 hash、版本、包名、签名要核对。
- **R03：真实 GitHub runner 和反馈固定依赖环境复验。** 本机通过不代替托管 runner 或生产容器版本核对。

SDK 扫描切换/重试、MCP 官方日志兼容、后台稳定性和 Android 完整制作闭环，已移到对应分支，不再作为本次功能验收项。

## 用户测试顺序

以下均待用户执行；旧浏览器/真机报告不能直接算本次通过。每轮记 APK hash、设备、GKD 版本和结果。更细步骤见 [回归清单](release-v0.2.0-regression-checklist.md)。

1. 保留数据覆盖安装，检查冷启动、设置、AI 配置、快照名、订阅缓存和测试记录。
2. 不连接 GKD，先从首页提交无附件的合成反馈，确认编号及后台唯一收件。
3. 测首页选快照、工作区及测试结果反馈；按需附规则/图片/节点；用合成数据验收打码和两处敏感文字。F01 修复后再判通过。
4. 提交阶段断网，重开/重启后恢复草稿，联网手动重试；确认不重复、成功清草稿，并清理后台合成反馈。
5. 官方 beta 路径：连接、快照、验证、追加本地规则，并在目标应用观察实际点击；响应失败后先核对是否已写入再重试。
6. 在独立环境测试官方正式版：连接、错渠道拒绝、复制后手动添加及实际效果。两种官方 APK 同包名，不要求在同一 Android 用户下并装，也不为测试卸载已有 GKD 数据。
7. 测选点、父子/重叠节点、唯一/多处/零命中、条件取消/应用、AI 候选、复杂原文保留及选中/命中标识。
8. 快速来回切换不同快照和应用；测多步排序、改绑和单/多步切换，确认最后选择及数据身份一致。
9. 测真实订阅库刷新、缓存失败、复制/测试/导入，以及实际 PNG/WebP 导出格式。各格式使用能够生成它的真实 GKD 版本验证。
10. 定发行范围、修复阻断项、提高版本并重构建后，对最终 hash 再测覆盖升级、反馈、导入和核心制作流程，之后才决定发布。
