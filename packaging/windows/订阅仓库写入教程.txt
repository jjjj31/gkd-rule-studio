GKD Rule Studio 订阅仓库写入教程

适用范围
1. 这个功能用于 Windows/Web 版和 Windows 便携版。
2. Android APK 不能直接写入 Windows 本地订阅仓库。
3. 浏览器需要使用 Edge / Chrome，并通过 http://127.0.0.1:5174/ 打开工具。

准备订阅仓库
1. 你需要有一个本地 GKD 订阅仓库文件夹。
2. 这个文件夹需要包含 package.json 和 src/apps。
3. 如果你已经有自己的订阅仓库，直接使用现有文件夹即可。
4. 如果还没有订阅仓库，可以先在 GitHub 上 fork 或创建一个 GKD 订阅仓库，再 clone 到电脑本地。

用 Claude Code / Codex / 其他助手准备仓库
1. 安装 Node.js 和 pnpm。
2. 打开 Claude Code、Codex CLI 或其他本地编程助手。
3. 让助手执行类似任务：
   - clone 我的 GKD 订阅仓库到本地
   - 安装依赖 pnpm install
   - 告诉我 src/apps 目录在哪里
   - 运行这个仓库自带的 lint / build / test 命令
4. 仓库能正常安装和校验后，再回到 GKD Rule Studio 写入规则。

连接本地订阅仓库
1. 解压 Windows 便携版。
2. 双击 START.cmd。
3. 浏览器打开 http://127.0.0.1:5174/。
4. 在首页连接手机或选择快照，进入工作区。
5. 在工作区选择目标控件和场景，确认右侧已经生成 JSON5 规则草稿。
6. 打开右上角设置。
7. 在“订阅仓库”里点击“连接本地订阅仓库”。
8. 选择订阅仓库根目录，也就是包含 package.json 的那个目录。
9. 浏览器弹出权限提示时选择允许。

写入规则
1. 连接成功后，点击“写入当前规则”。
2. 工具会写入或追加到 src/apps/<应用包名>.ts。
3. 如果这个应用文件不存在，会创建一个 defineGkdApp 文件。
4. 如果这个应用文件已存在，会把当前生成的 group 追加到 groups 里。
5. 工具写入的内容会带有 gkd-rule-builder:start / end 标记，方便之后撤回。

历史记录和撤回
1. “历史导入记录”会保留最近 30 条写入记录。
2. 如果某条规则写错了，连接同一个订阅仓库后点击对应记录的“撤回”。
3. 撤回会优先删除这次生成的标记块。
4. 如果这次写入创建了新文件，并且文件没有被手动改过，撤回会删除这个新文件。
5. 如果你手动改过文件，撤回前建议先自己检查一下 diff。

写入后怎么发布
1. 打开订阅仓库，检查 src/apps/<应用包名>.ts。
2. 用真实手机测试规则是否生效。
3. 运行订阅仓库自带的校验命令，例如 pnpm run lint、pnpm run build 或仓库 README 里写的命令。
4. 确认没问题后再 git commit、git push。
5. 发布方式以你的订阅仓库 README 或 GitHub Actions 配置为准。

常见问题
1. 看不到“连接本地订阅仓库”或按钮不可用：
   请用 Edge / Chrome 打开 http://127.0.0.1:5174/，不要用 Android 浏览器或普通 file:// 页面。

2. 提示“请选择订阅仓库根目录”：
   你选错目录了。请选择包含 package.json 和 src/apps 的目录。

3. 写入后规则没有生效：
   写入只代表把草稿放进仓库，不代表规则已经验证成功。需要在手机 GKD 里测试，并根据测试结果调整 selector、actionDelay、matchRoot、forcedTime 等参数。

4. 工具会不会自动提交或发布：
   不会。它只负责写入本地仓库文件。提交、推送、发布仍然需要你自己或本地助手完成。

5. 可以让 AI 助手继续处理吗：
   可以。把写入后的文件路径和测试结果告诉 Claude Code / Codex，让它帮你检查规则、运行仓库校验、整理 commit。
